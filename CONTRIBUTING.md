# Contributing to Fábrica de Mixes

Thanks for your interest! Bug fixes, documentation improvements, and focused features are welcome.
Start with the [README](README.md) ([Português](README.pt-BR.md)) to understand what the app does.

The web interface is in Brazilian Portuguese. You don't need to speak Portuguese to contribute, but
keep UI text in Portuguese and consistent with the existing pages. Code comments are also mostly in
Portuguese; comments in either language are fine.

## Prerequisites

- Git and a GitHub account.
- Node.js **≥ 22.18** (the app uses the built-in `node:sqlite`; CI uses Node 24).
- `ffmpeg` and `ffprobe` on your `PATH`.
- Optional: Docker Engine with the Compose plugin, to test the container setup.

## Workflow

1. Fork the repository and clone your fork.
2. Create a branch from `main` with a descriptive name, e.g. `fix-upload-limit`.
3. Make small, focused commits. Avoid unrelated refactors or formatting churn in the same PR.
4. Run the checks below, push the branch, and open a pull request against `main`.

## Running the app locally

Use an isolated, throwaway data folder so development never touches your real library:

```sh
npm ci
DATA_DIR=/tmp/fabrica npm run dev   # http://localhost:8080, reloads on save
```

`npm start` runs the server without watching. `PORT` and `MAX_UPLOAD_MB` can also be set as
environment variables (see `src/config.ts`).

> **Caution:** when run directly with Node (outside Docker Compose), the server listens on **all
> network interfaces**, and the app has no authentication or CSRF protection. Run it only on a
> trusted network, or block the port in your firewall. Docker Compose binds to `127.0.0.1` by default
> (`BIND_HOST` in `.env`, see [`.env.example`](.env.example)). See [SECURITY.md](SECURITY.md).

## Checks

Run these before opening a PR — CI (`.github/workflows/ci.yml`) runs the same commands on every push
and pull request:

```sh
npm ci
npm run typecheck
npm run smoke
```

`npm run smoke` (`test/smoke.mjs`) starts the real server with Node and ffmpeg in a temporary
`DATA_DIR`, generates short audio and image files, and walks through the main flow: channel, upload,
draft, review, approval, render, download, scheduling, and recording the publication. It uses no
external network access or credentials, cleans up after itself, and takes from seconds to a few
minutes, depending on the machine.

When you change behavior, extend the smoke test (or add a test) so that it fails without your change
and passes with it. Assert what a user observes — pages, responses, files, database state — rather
than implementation details. Documentation-only changes don't need tests.

## Where things live

TypeScript runs directly on Node (no build step), with Express 5, built-in SQLite, and ffmpeg. Pages
are server-rendered HTML with a little browser JavaScript.

| File | Responsibility |
| --- | --- |
| `src/server.ts` | HTTP routes, forms, uploads, and downloads; starts the render worker. |
| `src/config.ts` | Port, data folder, upload limit, and output format (1080p30, 320k audio). |
| `src/db.ts` | SQLite schema and access (`$DATA_DIR/app.db`). |
| `src/jobs.ts` | Draft selection, review, automatic mode, render queue, and worker. |
| `src/library.ts` | Upload handling, hash-based deduplication, and deletions. |
| `src/media.ts` | ffmpeg/ffprobe calls: visual loop, thumbnail, and mix render. |
| `src/views.ts` | HTML for every page. |
| `public/app.js` | File/folder uploads and live page updates during renders. |
| `public/style.css` | Styles. |

## Media and secrets

- Use only media you created or have the rights to use, and never commit audio, images, videos, or
  rendered output. Keep test media generated by the smoke test or local to your machine.
- Never commit your `.env`, data folder, database, logs containing personal paths, or any credentials.
  The app does not publish to YouTube; uploading rendered videos is a manual step and needs no
  tokens in this repository.
- Redact private information from screenshots and logs attached to issues or PRs.

## Reporting security issues

Do **not** open a public issue or PR for a vulnerability. Report it privately via GitHub's
**Security → Report a vulnerability** tab, as described in [SECURITY.md](SECURITY.md)
([Português](SECURITY.pt-BR.md)). The missing login and CSRF protection are documented limitations,
not new vulnerabilities.

## Pull request description

Please include:

- what changed and why (link the related issue, if any);
- how you tested it — the commands you ran and anything you checked manually in the UI;
- screenshots for visible UI changes;
- any impact on existing data, configuration (`.env`, Docker Compose), or the security model.
